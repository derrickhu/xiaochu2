# xiaochu2 新手引导设计

> **上位文档**：[00-体验目标.md](./00-体验目标.md)（主体验 = 编队聪明感）、[01-核心玩法循环.md](./01-核心玩法循环.md)
>
> 一句话方针：**全游戏只显式教一件事（长拖手势），其余全部交给关卡结构与已有的即时反馈；所有提示不遮罩、不锁操作、不打断。**

---

## 1. 为什么不照抄第一版

xiao_chu 第一版的引导是「全屏 72% 黑遮罩 + 小灵讲堂卡（必须点击才能过）+ 锁定拖珠路径（拖错自动补完）」，1-1~1-8 逐关一层，另有灵宠池 / 修炼 / 通天塔各自的气泡链。它的代价直接写在自己的注释里：

| 第一版实际发生的问题 | 出处 | 本版如何规避 |
|---|---|---|
| 第 1 章从 3 关扩到 8 关，引导文案未同步，玩家在 1-3 就看到「完成本章」，完全跳戏 | `js/engine/guideManager.js` 顶部「历史教训」 | 文案禁用相对进度描述，并加正则回归测试（§6） |
| 小灵死循环：在每帧 render 里 trigger，队列被塞满同 id | `guideManager.js:298` 防重复入队注释 | flag 一次性写入 + 同 id 不重入（§5.1） |
| 介绍卡「秒弹秒消失」，玩家来不及看 | `js/engine/tutorial.js:414` | 本版无阻塞卡，改为无操作才触发、可被玩家打断 |
| 4 步试炼关与序章爽局两套完整实现，**全项目无调用入口**，成为死代码 | 全库搜索无 `tutorial.start(` / `startNewbiePrologue(` | 只做 P0，不预埋「以后可能用」的框架 |

结论：引导做重的最大成本不是玩家嫌傻，而是它跟关卡设计强耦合——关卡一改，引导就说谎；改不动，就变成没人敢删的死代码。

## 2. 业界共识（对齐依据）

- **索尼 Team ASOBI（宇宙机器人）**：以示范而非文字教导玩家，游戏内尽量减少说明文字，用可实际操作的样例教新机制，**避免中断游玩节奏**。
- **铲子骑士复盘**：一次只教一件事；引导玩家亲自尝试而非强硬让他跟着走；反馈要即时明显；**不要为了教学中断玩家**；只在玩家需要用到时才教下一步。
- **塞尔达王国之泪初始空岛**：把机制拆进关卡结构，靠「教学—解谜—实践」循环形成肌肉记忆，全程无强制教程。

三者共同点：**教学的载体是关卡，不是 UI 浮层。** UI 浮层只用来补关卡教不了的那一点。

## 3. 认知断层分析：到底有几件事必须显式教

把新玩家需要掌握的知识点逐条过一遍，问「不说他能不能自己发现」：

| 知识点 | 能否自明 | 当前承载 |
|---|---|---|
| 长拖转珠（按住沿路径拖，沿途连续交换，限时 12s） | **不能** | ⚠️ **缺口** |
| 消 3 = 对应属性灵宠攻击 | 能 | 拖成一次即见：冲刺位移 + 受击闪白 + 伤害飘字 |
| 连击 = 高伤 | 能 | Combo 计数实时跳动 +「3 Combo ×1.4」倍率显示 |
| 心珠回血 | 能 | 掉血时玩家自会寻找生存手段，粉珠语义直观 |
| 技能释放 | 能 | `PetSkillReadyFx` 就绪箭头动画 |
| 五行克制 ×1.6 | **半能** | 战斗 HUD 敌人侧「克制 / 抵抗」胶囊、入场弹窗属性珠、编队页敌情条（三处口径一致）；但玩家不一定把它跟「我该换队」连起来 |
| 上阵灵宠属性决定可消珠色 | **不能**（盘面观察不到） | 无（列 P1 候选） |

**唯一致命的缺口是长拖手势。** 玩家带着消消乐习惯来，会去点两颗珠试图交换；一旦第一拖迈不出去，后面所有自明的反馈都无从发生。这是整份方案的重心。

「五行克制」不缺信息，缺的是**卡关那一刻的归因指向**——这正是 [00-体验目标](./00-体验目标.md) 审视清单第 1 条（卡关时是否把换队提示为比纯升级更短的路径）。而 [01-核心玩法循环](./01-核心玩法循环.md) §修正 2 早已承诺「卡关时明确提示：这关是水属性，招募 / 上场土系灵宠」，**代码至今未兑现**：失败弹窗对所有关卡固定显示同一句「提示：消除克制属性珠子伤害更高」，且与失败次数无关。P0-3 就是补这笔欠账。

## 4. P0 范围（本次上线版本）

### 4.1 引导进度存档

`SaveData` 新增 `tutorial: Record<string, boolean>`，随 save blob 走云同步，**无需**改 `CLOUD_SYNC_ALLOWLIST`（该表只登记独立 localStorage key）。

- 落点：`src/game/playerSave.ts`（`SaveData` 类型 + `initialData()` + `parseSaveData()` 补齐），`SAVE_VERSION` 7 → 8。
- 沿用现有迁移风格：无独立 migrate 函数，在 parse 时按字段 sanitize，缺失即空对象。
- **老玩家豁免（必须做）**：老档 `tutorial` 缺失时不能等同于「新手」，否则已通关十几章的玩家会被弹长拖示意。判定规则：`stars` 非空（有任何通关记录）即视为老玩家，迁移时把全部引导 flag 直接置为已完成。第一版正是靠云同步补写 4 个 key 来救这个场，说明踩过。

### 4.2 首页指路 + 长拖示意

**首页**：新号一进章节地图先出欢迎卡（「欢迎来到灵兽森林～」），点一下再圈选第一关（「点这一关，我们去冒险～」）。欢迎这一下有轻遮罩，指路阶段不锁操作。点进关卡详情即完成。

**战斗**：首次进入 `stage_1_1` 且 flag 未完成。**气泡进场即出**，手势约 0.35 秒后沿一条真实可消路径循环；字号正文 sm、头像 88px。

**硬性约束（与第一版的本质区别）**：

- 不加遮罩，不暗化棋盘。
- **不锁起点、不锁路径、不自动补完**。玩家从任意珠子起手都能拖，拖到哪算哪，拖出什么消什么。
- 玩家一碰屏幕，示意立即消失。
- 手势循环到玩家自己动手为止；播满上限也不自动标「学会了」。
- 玩家成功消除一次 → 立刻标记 flag 完成，本次会话不再触发。

它只是示范，不接管操作。这条是整个方案不许被侵蚀的底线。

### 4.3 失败提示按连败次数分档

`BattleResultOverlay` 已有 `_failCounts`（失败 +1、胜利清零），目前只计数不分支。改为：

| 连败次数 | 提示 | CTA |
|---|---|---|
| 第 1 次 | 沿用现有通用句 | 现有战力引导（`_buildGrowthGuide`） |
| **第 2 次起** | 读本关 `stage.element` 反查克制它的属性，指名道姓：「这关是火属性，上阵水系灵宠伤害 ×1.6」 | 首选改为**去编队** |

落点：`src/scenes/battle/BattleResultOverlay.ts` 的 `tipCopy`（约 537-539 行）与 `_buildGrowthGuide`。塔模式文案不变。

克制关系从现有五行数据反查，不新增配置。

### 4.4 新手漏斗埋点

SDK 里 `EVENT_NAMES.TUTORIAL_STEP = 'tutorial_step'` 早已存在（注释写着「每个游戏建议都接，否则无法分析新手流失」），业务从未调用。step_id 见 `analytics/index.ts` 的 `TUTORIAL_STEPS`：

`home_start_shown` → `home_welcome_continue` → `home_start_tapped` → `battle_enter_first` → `drag_hint_shown` → `first_touch`（首次落指）→ `first_match`（首次成功消除），另有 `drag_hint_dismissed` 与 `coach_team_pick`（卡关指路后选择去编队）。

两个刻意的取舍：

- **前 3 关的通关节点不重复埋**。`level_clear` 已带 `level_name=stage_1_1`，漏斗直接拼它即可；两套口径并存只会让后面的人不知道该信哪个。
- **不埋「首次改动编队」，改埋「卡关后选择去编队」**。后者只需一处改动（编队入口就在失败弹窗里），而且直接测量「卡关 → 换队」这一跳，比「改过编队」更贴 §8 的验收标准。

**这项的价值可能高于前三项**：它是唯一能证明引导有效或无效的东西。第一版做了整套引导却没有漏斗，改了几轮方向全靠猜，最后留下两套死代码。

## 5. 小灵：极轻登场

### 5.1 出场节点（本版共 2 处）

| # | 时机 | 形式 | 归属 | 现状 |
|---|---|---|---|---|
| 0 | 首次进入章节地图 | 先欢迎卡，点继续后再圈选第一关 | 首页 | 已实现 |
| 1 | 1-1 首战进场 | 大号气泡立刻出字，0.35 秒后手势循环；不遮罩，玩家一碰即消 | P0-2 | 已实现 |
| 2 | 连败第 2 次起 | 失败弹窗指名克制句 | P0-3 | 已实现 |
| 3 | 前 3 关战斗 | 做对了点破 / 连续打不好再补：连击、克制各一句 | 局内 coach | 已实现 |
| 4 | 前 3 关编队 | 珠色=上阵属性；缺克制色则改口换成队 | 编队页 | 已实现 |

不做引导链。同一条知识 praise / nudge 互斥，一场同一回合最多一句。

### 5.2 文案

两句，全文如下，不做多页：

- 首页欢迎：**「欢迎来到灵兽森林～ / 我是小灵，往后由我陪你闯关。」**（`HOME_WELCOME_TIP`）
- 首页指路：**「点这一关，我们去冒险～」**（`HOME_START_TIP`）
- 战斗：**「按住珠子，顺着路一直拖过去～」**（`dragHintPath.ts` 的 `DRAG_HINT_TIP`）
- 连败第 2 次：**「这关是{X}属性，上阵{Y}系灵宠伤害 ×{倍率}」**（`defeatCoaching.ts`）
- 连击点破 / 补课：`COMBO_PRAISE` / `COMBO_NUDGE`
- 克制点破 / 补课：`counterPraiseText` / `counterNudgeText`
- 编队：**「上阵灵宠的属性，决定你能消哪种珠」**；缺克制色则改口带系

`{X}` `{Y}` 由关卡属性与 `counterElementOf` 算出；倍率读 `COMBAT.counterMultiplier`，**不许写死**——`00`/`01` 两份文档里写的 1.6 早就被调成了 1.75，写死会当场说谎。

文案纪律（防第一版跳戏）：**禁止出现「本章 / 最后一关 / 章末 / 还剩 X 关」等相对进度描述**，禁止出现具体关卡编号以外的进度承诺。由 §6 回归测试强制。

### 5.3 资源与加载（硬约束）

第一版的立绘直接复用：`xiao_chu/assets/ui/guide_xiaoling.png` → `images/ui/guide/xiaoling.png`（主包），256×256、95.8KB。

必须放主包：首页一进来就要说话，挂 pkg-battle 等于新号先下 2MB 分包才看得到指路。仍然**不进任何预加载清单**（首屏 / 延后 / 战斗 shell 都不含）。`assetPreloadBudget.test.ts` 有护栏兜着。

**降级要求**：贴图未就绪时，气泡必须能只显示文字照常工作。

## 7. 明确不做

以下均为第一版做过、且本版**主动放弃**的内容。列在这里是为了将来有人想加时，先回来看一眼理由：

- 开场漫画 / 序章爽局
- 全屏遮罩讲堂卡（任何形式的阻塞式教学弹窗）
- 锁定拖珠路径、拖错自动补完
- 1-1~1-8 逐关教学链
- 跨界面引导队列 / 引导接力 / 引导优先级编排
- 灵宠池、修炼、通天塔等系统的入门气泡
- 任何「引导框架」式的通用基建（等到真有第三、第四处需求再抽）

## 8. 验收标准

对齐 [00-体验目标](./00-体验目标.md) §7：

| 维度 | 标准 |
|---|---|
| 第一拖 | 埋点上 `first_match` / `battle_enter_first` 转化率 ≥ 95%；示意平均播放次数 < 1.5 |
| 教学重点 | 前 3 关后玩家能说出「属性 / 队伍有用」（对齐 01 文档 §4） |
| 卡关归因 | 连败 2 次后，玩家下一步动作偏向进编队而非只去升级 |
| 不打断感 | 玩家不会为了跳过引导而反复点屏；`hint_dismissed` 中「主动打断」占比高说明示意时机合适（玩家本来就会动手） |
