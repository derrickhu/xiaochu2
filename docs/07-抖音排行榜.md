# 通天塔排行榜（方案）

> 榜单数据全平台只有一份：CloudBase 自建云榜。皮肤自己画（主域 Pixi 弹窗）。
> 抖音官方 IM 榜只保留写入，界面不读它。第一版只做通天塔总榜。

## 1. 排什么、不排什么

| 候选 | 结论 | 原因 |
|---|---|---|
| **通天塔历史最高层** `tower.bestFloor` | **第一版只排这个** | 长线、可比、无章关封顶 |
| 好友榜 | 第二期 | 先把总榜和首页入口做稳 |
| 通天塔本周最高层 | 第二期 | 要本地按周另记一份 |
| 主线 / 秘境 / 战力 / 货币 | 不做 | 封顶、日墙或和广告挂钩 |

产品定义：**比的是通天塔历史上爬到过的最高层。**

## 2. 为什么不用抖音官方榜做展示

一度是「官方榜供数 + 自绘皮肤」，读别人的名单只能靠开放数据域 `tt.getImRankData`。这条路有三个硬伤：

- **鸿蒙整条不可用**：`tt.setImRankData` / `tt.getImRankData` / 开放数据域都没有，鸿蒙上是空榜
- **两层画布画同一批人**：主域画自己、开放数据域画官方名单，同一个人被画两次，名字互相重叠，名次还会打架
- **官方榜人更少**：只收开过新包并成功写入的账号，实测比云榜少一个数量级

所以榜单一律读云榜。抖音的 `setImRankData` 还在写，几行代码，为的是将来想用抖音原生榜入口时不用重接。

## 3. 云榜怎么存

按平台分表：`pettower_tt_towerRank`（抖音）、`pettower_hw_towerRank`（鸿蒙）等，`floor` 建降序索引。

一行一个玩家：`userId` / `platform` / `floor` / `name` / `avatarUrl` / `updatedAt`。

接口（`cloudfunctions/petTower-api`）：

- `POST /rank/tower`：前 10 名 + 自己那条（掉出前 10 也带真实名次，按「比我高的人数 + 1」算）
- `POST /rank/tower/report`：上报自己的层数 / 昵称 / 头像
- `POST /rank/tower/backfill`：只能事件调用，把已有存档里的 `bestFloor` 灌进榜；上新时用一次

存档 push 成功时也会顺手 upsert 一次，所以正常玩就会自己维护。

昵称头像来自宿主平台资料，玩家自己上报。没上报过的显示 `仙灵xxxx` 占位。

## 4. 写入与入口

写入时机：破纪录、直登、进通天塔页补写。云榜必写；官方榜 `bestFloor === 0` 不写，与上次成功写入相同则跳过。

打开排行时先 `ensureHostProfile()` 再上报，否则榜上自己会是占位名。

入口：首页左栏第一格「排行」。通天塔页「最高 N ›」仍可进同一页。不进底栏。

全页用宣纸底板 `scene_rank.jpg`（四周园林，不当山路画布）。圆环 / 台座走流水线零件；名单行按原型做成宣纸卡片；标题匾和「炫耀一下」用游戏组件。不设好友榜，进页就是通天塔总榜。

## 5. 工程切分

- `PlatformService`：`setImRankData` / `ensureLogin`
- `game/rankService.ts`：分区、去重、补写
- `game/rankCloud.ts`：云榜取数 / 上报（榜单唯一数据源）
- `game/rankBoard.ts`：领奖台 / 列表收口规则（按层数定名次、同一个人只出现一次）
- `ui/RankPanel.ts`：主域弹窗（宣纸底板、匾额、历史最高层、炫耀），盖在当前场景上
- 挂点：`battleContextSettle`、`towerEventResolve`、`TowerScene` 直登与进场

## 6. 分期

- **P0（本期）**：云榜总榜自绘 + 首页入口 + 破纪录写入
- **P1**：好友榜；或本地「本周最高层」
- **P2**：阵容快照（`extra` 不够，要另存）

## 7. 验收

- 抖音真机 / 鸿蒙真机：看到同一份名单，自己有名次，没有重名重叠
- 别人的抖音头像能显示（头像 CDN 域名要在抖音后台下载白名单里）
- 微信 / 浏览器能开同一页，接口不通时至少看见自己的最高层，不报错
- 未登录 / 接口失败：爬塔照常
