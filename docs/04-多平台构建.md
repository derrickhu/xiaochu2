# 多平台构建（微信 / 抖音 / TapTap）

对齐 `code_1` 的 `platform/` + `build/<平台>/` 组装。游戏内容一份，平台差异只放在壳和编译目标里。

## 1. 为什么这样拆

| 做法 | 问题 |
|---|---|
| 共用一个 `minigame/`，两份 `project.config.json` 拆在根目录和子目录 | 每加一端都要绕；`game.json` 还得同时写 `subpackages` / `subPackages` |
| 只换 Vite `outDir` | 资源树和工具工程搅在一起，watch / 上传路径混乱 |
| 一份 bundle 打 Tap | Tap 运行时是 `tap.*`，和 `wx`/`tt` 不是兼容层，会把抖音包污染进去 |

业界对应关系：

- **Cocos / Unity**：一个工程、多个 Build Target，产物是 `build/wechatgame`、`build/bytedance`
- **微信 + 抖音**：API 几乎同构 → **一份 bundle + 运行时认宿主 + 每端一份 json**（code_1）
- **Tap 小游戏**：独立运行时 → **第三套 Build Target**，单独打 bundle

xiaochu2 用两层融合：外壳学 code_1，Tap 内核编译期分流。

## 2. 目录

```
minigame/                 共享内容树（game.js / runtime / pixi-adapter / 图 / 分包）
                          不是开发者工具打开的目录
.bundle/                  Vite 产出：微信 / 抖音共用 game-bundle.js
.bundle-taptap/           Vite 产出：仅 Tap（VITE_PLATFORM=taptap）
platform/wechat|douyin|taptap/    各端 game.json、project.config.json
build/wechat|douyin|taptap/       开发者工具 / 打包工具打开这里
```

`minigame/` 是资源与启动脚本的**唯一真源**（入库）；CDN 扫描、`organize-subpackages` 只对着它。`build/<平台>/` 是生成物（不入库、不手改），和 Cocos 的 `build/wechatgame` 一样会带一份普通文件树，给开发者工具 / Tap 打包用。不要在 `build/` 里改图，也不要用软链。

组装默认走增量镜像（`scripts/lib/mirror-tree.mjs`）：同大小且 mtime 相差 ≤1s 才跳过，否则真源覆盖；原子替换；拆软链/硬链。`npm run build` 在 organize 之后才组装。`npm run dev` 改 TS 刷 bundle，改 `minigame/` / `platform/` 只增量拷，不重打 JS。需要整目录重铺时：`node scripts/build-platform.mjs --full`。

## 3. 命令

| 命令 | 打开哪里 | 给谁 |
|---|---|---|
| `npm run build` | `build/wechat/` + `build/douyin/` | 默认两端 |
| `npm run build:douyin` | `build/douyin/` | 抖音提审 / 预览 |
| `npm run build:wechat` | `build/wechat/` | 微信 |
| `npm run build:taptap` | `build/taptap/` | Tap 扫码自测 / 打 zip |
| `npm run dev` | 同上（watch：改 TS / 改图都会增量组装） | 日常模拟器 |

抖音开发者工具请打开 **`build/douyin/`**，不要再开 `minigame/`。appid 仍是 `tt64d6126bfab7cc5502`，后台当普通版本更新即可。

日常自动进模拟器：终端挂着 `npm run dev`，工具打开对应 `build/<端>/`，并保持「修改文件时自动编译」（抖音还要开这个，热重载本身不支持小游戏）。改 `src/` 或 `minigame/` 会写入 `build/` 并轻碰 `game.js`，模拟器应自己重开，不用再点编译。真机预览 / Tap 扫码不会自动，要重新出码。

## 4. 隔离点

1. **输出目录**：各端互不覆盖。
2. **编译常量**：`VITE_PLATFORM=taptap` 时 `PlatformService` 固定为 Tap，抖音包里没有这条分支。
3. **存档前缀**：抖音 `petTower_tt_*`，Tap `petTower_tap_*`，微信 `petTower_*`。
4. **广告 / 订阅**：Tap 空配置，不会误用抖音 adUnitId / 模板 ID。
5. **登录**：Tap 第一期走游客（`anon`），接上 `tap.login` 后再把后端 `platform: tap` 打通。

业务代码继续只调 `Platform.*`，禁止写 `typeof tt` / `typeof tap`。
